Coming back up is different because a restored neighbor is only considered healthy after a fresh Hello is seen, whereas a failed one is detected by silence and the dead timer.

Task 3: I keep the current best-distance map and next-hop table between events, which costs a little memory but avoids repeated full SPF work on events that do not change the shortest-path tree. The main remaining full recomputation is needed when a link failure or a cost change actually creates or removes a usable shortest path; a pure Python router is slower in wall time than the baseline because of bookkeeping overhead, but on a real router that trade-off is the right one because correctness under churn matters more than bare Python speed.
